# PS 06 (Project Brain): requirement mapping

How each item of the problem statement is met, how to see it, and what is still partial. Counts
are for Online Boutique as ingested on 2026-10-31 (`make stats` prints the current ones).

## Minimum working version

| Requirement | How Hindsight meets it | See it |
|---|---|---|
| **Project history collection** from commits, tickets, chat and documents (a public project is allowed as a stand-in) | Git history (2,700 commits); public GitHub issues and PR descriptions (2,800 PRs and 67 issues with text, plus the issues the history explicitly closes, fetched one by one); every Markdown doc in the repo; uploaded PDF/Markdown docs. **Partial:** issue and review comments are fetched by the same reader but are not in the demo data yet (GitHub's hourly limit without a token); there is no chat importer (Slack is a future idea) | `make ingest`, `make stats`; **More › The data** |
| **Connected memory**: link a commit to its ticket and to the discussion about it | Commit → PR (2,106 confirmed by GitHub's merge commit, 221 more from the `(#N)` title suffix), PR/commit → issue (63 explicit "Fixes #N", plus mentions), comment/review → PR or issue, file → service, service → service (calls read from the code), doc section → service/file, commit → author, file ↔ file (changed together). Every link records how it was found and its evidence | **Map**; `GET /api/graph?view=services` |
| **Question answering** ("why was this code written this way?") **with sources** | Starts from what the question names: a file, a service, a commit hash, or a function or class (its lines → `git blame`); follows commit → PR → issue → discussion; adds keyword and (optional) semantic search; explains for a newcomer and walks through the code; every claim cites its source with a link | **Ask**; `uv run hindsight ask "…" [--file F --lines A-B]` |
| **Impact check** with a reason for each item | Files, services, tests to re-check, docs that may need updating (and whether they already look out of date), runbooks and people to ask, each with reasons such as "changed together in 20 of 39 commits (last 0434be5)" or "frontend calls checkoutservice (src/frontend/handlers.go:354)" | **Impact**; `uv run hindsight impact --files … \| --commit SHA` |

## Bonus goals

| Bonus | Status |

## Rules

| Rule | How it's enforced |
|---|---|
| Cite sources | Every claim carries citation ids; code drops any claim whose citation is not in the evidence pack or whose cited text does not contain its key words; a model check can only remove claims |
| Say "not found" | Abstains when the best evidence covers less than 60% of the question's (rarity-weighted) words and nothing reaches the named code's history; shows the 3 nearest items |
| Public or sample data only | Online Boutique is public (Apache-2.0); GitHub is read-only; test fixtures are synthetic and labelled |

## Measured (`make eval-ask`, `make eval`; **Proof**)

- **Why-answers** (`docs/EVALUATION.md` §3): 25 questions generated by code from "Fixes #N" links.
  Naming the commit, the issue behind it is among the sources and cited in 100% (keyword search
  alone finds it in 60%). Naming only the file and the change: answered 92%, issue among the
  sources 64%, cited 28%. Trick questions (hand-written, right answer "not found"): to be measured.
- **Impact** (§2): replay of 74 held-out commits: R@10 0.611 vs 0.413 same-folder and 0.581
  co-change only (intervals overlap with co-change); same protocol on eShop and the OpenTelemetry Demo.

## Extras

- Bot share is measured and filtered (65% of Online Boutique's commits are automated updates);
  PRs and issues opened by bot accounts are never used as evidence.
- Docs that may be out of date: what they describe kept changing after their last edit (**Docs**).
- Instruction-like text in ingested content is flagged, shown as evidence only, never sent to a model.
- Optional language-model phrasing (Gemini → Groq → Ollama) with a record/replay cache and secret scrubbing.
