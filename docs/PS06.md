# PS 06 (Project Brain): requirement mapping

How each item of the problem statement is met in phase 1, and how to see it for yourself.

## Minimum working version

| Requirement | How Hindsight meets it | See it |
|---|---|---|
| **Project history collection** from commits, tickets, chat and documents (a public project is allowed as a stand-in) | Git history of Online Boutique; its public GitHub issues (tickets), PR descriptions, issue/PR comments and review comments (discussions); every Markdown doc in the repo | `make ingest`, `make stats`; dashboard **Overview** |
| **Connected memory**: link a commit to its ticket and to the discussion about it | Commit → PR (title `(#N)`, confirmed by GitHub's merge commit), PR/commit → issue (`fixes #N` or a mention), comment/review → PR or issue, review → file, file → service, service → service (calls in code), doc section → service/file, commit → author, file ↔ file (changed together). Every link records how it was found and its evidence | Dashboard **Map**; `GET /api/graph?key=service:checkoutservice` |
| **Question answering** ("why was this code written this way?") **with sources** | Starts from the named code (or `git blame` on given lines), follows commit → PR → issue → discussion, adds keyword search; every claim cites its source with a link | Dashboard **Ask why**; `uv run hindsight ask "…" [--file F --lines A-B]` |
| **Impact check** with a reason for each item | Files, services/components, tests to re-check, docs that may need updating and people to ask, each with reasons such as "changed together in 20 of 39 commits (last 0434be5)" or "frontend calls checkoutservice (src/frontend/main.go:…)" | Dashboard **Impact**; `uv run hindsight impact --files … \| --commit SHA` |

## Bonus goals

| Bonus | Status |
|---|---|
| Visual map of code, tickets and people | Done: dashboard **Map** (search any service, file, PR, issue or person) |
| Pull request check | **Dropped by decision**: nothing is posted to GitHub. The impact check works on any commit or file list |
| Knowledge at risk | Done: dashboard **Knowledge at risk**: files only one person worked on (with activity status) and bus factor per component |

## Rules

| Rule | How it's enforced |
|---|---|
| Cite sources | Every claim carries citation ids; the code drops any claim whose citation isn't in the evidence pack or whose cited text doesn't contain its key words |
| Say "not found" | Abstains when the best evidence covers less than 60% of the question's (rarity-weighted) words, and reports question words that appear nowhere in the history; shows the 3 nearest items |
| Public or sample data only | Online Boutique is public (Apache-2.0); GitHub is read-only; test fixtures are synthetic and labelled |

## Extras from the 36-hour plan

- Bot share is measured and filtered (65% of Online Boutique's commits are automated dependency updates).
- The impact check is evaluated by replaying held-out history against three baselines, with confidence
  intervals: `make eval` → [eval/results/latest.md](../eval/results/latest.md); dashboard **Accuracy**.
- Instruction-like text in ingested content is flagged, shown as evidence only, and never sent to a model.
- Optional language-model phrasing (Gemini → Groq → Ollama) with a record/replay cache and secret scrubbing.
