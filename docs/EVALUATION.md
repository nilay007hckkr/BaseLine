# Hindsight: Evaluation (36-hour edition)

These rules apply to every number in this document:
- Every number comes from `make eval` and is written to `eval/results/<name>-<timestamp>.json`, together with its config.
- Every metric is shown with a **baseline**, the sample size **n**, and a **95% bootstrap CI** (1,000 resamples, seed 13).
- Synthetic setups (mutations, injected faults) are labelled synthetic.
- If a result is worse than its baseline, show it anyway.

Other public repositories are evaluated with the same protocol and the same default weights,
each in its own data folder (`make try-repo REPO=<url>`); `eval/results/latest.md` lists them
separately from the main repository. Nothing is tuned on them.

## 1. Splits and leakage
- History is split by time: oldest 70% for statistics, next 15% for validation (tuning weights and thresholds), newest 15% for testing.
- Replay queries only use rows with `ts <= query commit time`.

## 2. Blast radius (history replay)
- **Queries:** test-split commits with 2–30 files, excluding bot, sweep, generated and merge commits.
- **Protocol:** reveal one file (seed-fixed) and predict the rest.
- **Metrics:** P@5, R@10, Hit@3.
- **Baselines:**
  - same directory (most recent first);
  - most frequently changed files;
  - co-change only (no static, service or recency signals).
- **Ablation:** with and without bot/sweep filtering. Report the bot share.

## 3. Why-answers

Mixed answer key (decided 2026-10-31), so that the team does not pick the questions it is graded on.
`make eval-ask-questions` writes the answerable set; `make eval-ask` scores both sets and writes
`eval/results/ask-*.json` (with the code SHA and one row per question) plus a hand-check CSV.

- **Answerable** (`eval/questions.yaml`, generated by code, never edited by hand):
  - one question per commit that closes an issue explicitly ("Fixes #N", on the commit or on the
    PR it belongs to), when issue N's text was read; bot, sweep and merge commits are left out;
  - the question names a file the commit changed, the commit hash and its subject with issue
    numbers and closing keywords removed: *Why was `src/x/main.go` changed in commit `abc1234`
    ("subject")?*, as a newcomer would ask after `git blame`;
  - gold: issue N, the reason the change was made.
- **Trick** (`eval/questions-trick.yaml`, written by hand; template in
  `eval/questions-trick.example.yaml`): ≥ 10 false premises, changes that never happened and
  questions the history cannot answer. The right answer to each is "not found". The current 12
  were written on 2026-10-31 after the answerable results had been seen (not blind) and committed
  (`c7d96a5`) before they were first scored; git shows the order.
- **Metrics** (95% bootstrap CI, 1,000 resamples, seed 13):
  - answerable: answered; the linked issue among the sources; the linked issue cited by a claim;
  - trick: answered "not found".
- **Baselines:**
  - keyword search alone (FTS5 BM25, no graph): is the linked issue among its top 12 results
    (the same number of sources an answer shows)?
  - the same model without any sources, when a model is configured: how often it "answers" a
    trick question. Not run, and not reported as 0, when no model is configured.
- **Hand check:** 10 answered questions (every n-th) go to a CSV; a person marks each supported or
  not. Reported separately, never folded into the automatic numbers.
- **Scope:** scored on the full graph. Ask explains changes that already happened, so this is not
  a prediction task and the replay rule of §1 does not apply. The answerable set only covers
  history with explicit links; it does not measure questions phrased in other words.
- **Two variants per answerable question.** Naming the commit hash lets the commit's own links lead
  to the issue, so that variant is close to guaranteed by the graph. The second variant drops the
  hash and keeps only the file and the change's subject: search must find the commit first. Both
  are reported; the second is the telling one.
- **What the runs changed, in order (same 25 questions, so the later numbers are in-sample):**
  1. Before any number was recorded, the generated questions showed two bugs (fixed with tests):
     a commit hash counted as an unmatched word (now it anchors that commit, like `git blame`),
     and keyword search missed words whose porter stem is shorter than six letters
     ("rounding" → "round").
  2. First recorded run (`ask-20261031T223810Z.json`, Ask code `a9622d3`): with the file and
     change only, answered 0.84, linked issue among the sources 0.52 (keyword search alone 0.60),
     cited 0.28. Cause: for a named file, Ask followed only its 40 latest commits.
  3. Fix: also follow the file's older commits whose message matches the question
     (`ask-20261031T224009Z.json`, code `c88a6c9`): answered 0.92, among the sources 0.64,
     cited 0.28. With the hash: 1.00 on all three. The intervals still overlap with keyword
     search; the trick questions (unseen) are the check that this did not make Ask answer more
     when it should not.
  4. First trick run (`ask-20261031T230310Z.json`, code `c7d96a5`, quoted answers): only 6 of
     12 answered "not found". Every wrong answer passed on common words ("moved", "removed",
     "store", "next year") while its most specific word (MongoDB, Docker Swarm, PostgreSQL,
     Elasticsearch) appeared in no source. Rule added: the sources that cover the question must
     contain its rarest word, or the answer is "not found" (blame and named-commit answers keep
     their path). Result (`ask-20261031T230652Z.json`, code `7c202ea`): trick "not found" 9 of 12
     (0.75); with the file and change only, answered 0.88, issue among the sources 0.60, cited
     0.24 (was 0.92 / 0.64 / 0.28); naming the commit, still 1.00. Still answered: "Why was
     adservice removed?" (the false word is common), "Why does currencyservice store its rates in
     PostgreSQL?" and "Who will maintain paymentservice next year?" (a question about the future).
     The trick set is now in-sample for this rule; a new blind set is the real test.
- **Model runs:** not yet recorded. On the build machine the local Ollama install lacks its model
  runtime (HTTP 500 on every call), so every number above is for quoted answers; the
  plain-model baseline needs a working model.
- **Failure analysis (file + change variant, `c88a6c9`):** 9 of 25 miss the issue. Most name busy
  files (README.md, skaffold.yaml, .travis.yml) where many other commits share the question's
  words; 2 end in "not found" because the matching text does not name the file. Another 9 find
  the issue but quote other sources first: quoted answers lead with the best-covering passages,
  and the issue's wording is often further from the question than the commit's.

## 4. Healing (mutation harness)
- **Cosmetic mutations** (the healer should heal): id rename, class rename, a wrapper element inserted, sibling reorder, button text change that keeps its meaning. At least 20.
- **Real-defect mutations** (the healer must refuse): element removed, control disabled, backend returns an error (env-gated fault), wrong total shown. At least 5.
- **Metrics:** heal rate, **false heals (target 0)**, correct refusals, heal latency.
- **Baselines:** no healing; naive "first element with the same tag and text".

## 5. LogSense
- **Fault campaign:** at least 10 injections across scenarios (checkout error, latency via `tc netem`, scale-to-zero, crash loop) and services, each with ≥ 5 minutes of healthy traffic before it. Ground truth is written by `make fault`.
- **Metrics:** top-1 and top-3 culprit accuracy, median time to detect, false alerts per hour during healthy periods.
- **Baselines:** "service with the most error lines"; "service with the largest error-rate increase".
- **Optional (if time allows):** BARO from the RCAEval package on RE2-OB, reported as outside context, not as a head-to-head comparison.

## 6. Correlation
On injected-commit runs, report the guilty commit's rank (Hit@1, Hit@3) against the baseline "most recent deploy".

## 7. Scorecard
`GET /api/scorecard` reads the latest result files. Each card shows the metric, value, baseline, n, CI and the reproduce command.
